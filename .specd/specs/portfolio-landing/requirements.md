# Requirements — portfolio-landing

Portfolio landing page showcases developer's work and enables visitor engagement.

## Display & Discovery

- **R1** When visitor lands on homepage, system shall display hero section with developer name, title/tagline, and call-to-action (CTA) to contact or view work.
- **R2** When visitor scrolls, system shall display "Latest Articles" section showing 3–5 most recent blog posts with title, excerpt, date, and link.
- **R3** When visitor scrolls, system shall display "Latest GitHub Projects" section showing 3–5 most recent public repositories with name, description, star count, and link to GitHub.
- **R4** When visitor scrolls past main sections, system shall display footer with contact options (email, GitHub, LinkedIn, Twitter) and copyright.

## Trust & Credibility

- **R5** When visitor views article, system shall display author info (name, bio, avatar) and publication date to build author credibility.
- **R6** When visitor views GitHub project, system shall display repository metadata (language, stars, forks, last updated) to demonstrate project maturity.
- **R7** When visitor lands on homepage, system shall prominently display a technical/professional bio (50–100 words) to establish expertise.

## Engagement

- **R8** When visitor wants to contact, system shall provide contact form or direct link to email/contact page with fields for name, email, and message.
- **R9** When visitor clicks external link (GitHub, blog post, social), link shall open in new tab and preserve homepage navigation context.
- **R10** When visitor accesses landing page on mobile, system shall render responsively with readable text, touchable buttons, and proper spacing on screens ≤768px wide.
